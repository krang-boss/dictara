## 1. Решение по платформе: остаёмся на Rust + Tauri

Вопрос «Rust или Swift» закрыт в пользу **Rust + Tauri**. Обоснование:

- Хотелки — это **на 90% UI-работа** (окно меню-бара, история, переключатель
  моделей, редизайн попапа). Язык ядра к ним отношения не имеет.
- Единственный весомый аргумент за Swift был — убрать WebView ради лёгкости.
  Но пункт 3 (полноценное окно из меню-бара со списком истории) — это ровно то,
  что дёшево делается в вебе и дорого в AppKit. Переезд на Swift сделал бы
  желаемые фичи **дороже**, а не легче.
- Отказ от локальной транскрипции сам по себе даёт большую часть выигрыша
  по весу, который ожидался от Swift (см. §2).
- Проект для себя → нет давления по размеру бандла и по «нативности ради
  App Store review».

> Замечание к пункту 4: **настоящее стекло в вебе не получится.** CSS
> `backdrop-filter` размывает только то, что внутри страницы, а не то, что
> под окном. Для реального macOS-стекла нужен `NSVisualEffectView` под
> прозрачным WebView — это делается на стороне Rust через крейт
> [`window-vibrancy`](https://github.com/tauri-apps/window-vibrancy).
> То есть стекло — это несколько строк нативного кода + прозрачный фон в CSS.
> Отдельно: «Liquid Glass» из macOS 26 — это нативный AppKit API,
> из WebView его не достать; из Tauri доступны классические vibrancy-материалы
> (`.sidebar`, `.hudWindow`, `.popover`, `.underWindowBackground`). Для наших
> целей их достаточно.

**Что при этом всё же стоит сделать нативным:** попап записи. Он живёт постоянно
и держит целый WKWebView ради маленького оверлея. Но это решаем на этапе редизайна
попапа (§4.5), а не сейчас — сначала надо понять, каким он станет.

## 3. Архитектурная проблема №1: модель конфигурации

Это главное, что придётся переделать, и от этого зависят фичи 1, 2 и 3.

### Как сейчас

Модель зашита **внутрь конфига провайдера, который лежит в Keychain**:

```rust
OpenRouterConfig    { api_key, model }        // Keychain
ElevenLabsConfig    { api_key, model_id }     // Keychain
CustomEndpointConfig{ api_key, base_url, model } // Keychain
OpenAIConfig        { api_key }               // модели нет вообще
AzureOpenAIConfig   { api_key, endpoint }     // модель в endpoint
```

А активный выбор — одно поле:

```rust
AppConfig { active_provider: Option<Provider>, ... }
```

Три проблемы:

1. **Один провайдер = одна модель.** Структурно нельзя иметь два варианта
   одного провайдера.
2. **Модель живёт в Keychain.** Смена модели = запись в Keychain. Это медленно,
   вызывает диалоги доступа и концептуально неверно: модель — не секрет.
3. **Провайдеры неоднородны.** У OpenAI модели нет, у Azure она внутри URL,
   у остальных — отдельным полем. Общего интерфейса нет.

### Куда идём: пресеты

Разделяем две сущности:

**Credentials** (Keychain, по одной записи на провайдера) — только секреты:
```rust
OpenAICredentials  { api_key }
OpenRouterCredentials { api_key }
CustomEndpointCredentials { api_key: Option<String> }
```

**Preset** (обычный Store, не Keychain) — именованный вариант «чем транскрибировать»:
```rust
struct Preset {
    id: Uuid,
    name: String,            // "Whisper быстрый", "ElevenLabs RU"
    provider: Provider,
    model: String,           // для Azure — deployment
    base_url: Option<String>,// Custom Endpoint / Azure
    language: Option<String>,
    prompt: Option<String>,  // system/initial prompt, если провайдер умеет
    audio_format: AudioFormat,
}

struct PresetsConfig {
    presets: Vec<Preset>,
    active_id: Option<Uuid>,
}
```

Что это даёт:
- Несколько моделей одного провайдера — бесплатно.
- Переключение пресета = запись в JSON-store, без Keychain и без диалогов.
- Переключение из меню-бара и с хоткея — тривиально.
- История может ссылаться на `preset_id` → видно, чем расшифровано.
- Пер-пресетные настройки (язык, промпт, формат) вместо глобальных.

**Миграция:** одноразовая функция по образцу `migrate_trigger_to_shortcuts()`
в `config.rs` — читает старые пер-провайдерные конфиги, создаёт по пресету
на каждый настроенный провайдер, переносит `active_provider` в `active_id`,
секреты в Keychain оставляет как есть (только чистит из них поля моделей).

### 4.2 История голосозаписей

Первое решение — **где хранить**.

| Вариант | За | Против |
|---------|-----|--------|
| JSON в Store | ничего не добавлять | не тянет тысячи записей, нет поиска |
| **SQLite (`rusqlite`)** | поиск, пагинация, растёт нормально | +зависимость |
| SQLite через `tauri-plugin-sql` | миграции из коробки | тянет sqlx, тяжелее |

**Рекомендация: `rusqlite` (bundled).** История — единственная таблица,
sqlx здесь избыточен. Схема примерно:

```sql
CREATE TABLE recordings (
  id            INTEGER PRIMARY KEY,
  created_at    INTEGER NOT NULL,       -- unix ts
  duration_ms   INTEGER NOT NULL,
  text          TEXT NOT NULL,
  preset_id     TEXT,                   -- чем расшифровано
  provider      TEXT,
  model         TEXT,
  audio_path    TEXT,                   -- NULL если аудио не хранится
  app_bundle_id TEXT,                   -- куда вставили
  status        TEXT NOT NULL           -- ok / failed
);
CREATE VIRTUAL TABLE recordings_fts USING fts5(text, content=recordings);
```

Аудио — файлами в `~/Library/Application Support/app.dictara/recordings/`,
в БД только путь.

Решить:
- [ ] Хранить ли аудио вообще? (Кандидат: хранить N последних / до X ГБ,
      старое чистить. Иначе диск съестся быстро.)
- [ ] Ретеншен: сколько дней/записей?
- [ ] Что делать с провалившимися транскрипциями — хранить аудио для ретрая? Да, вероятно.
- [ ] Нужно ли редактирование текста в истории?
- [ ] Действия по записи: копировать, вставить снова, ретранскрибировать
      другим пресетом (это сильная фича — аудио уже есть), удалить.
- [ ] `app_bundle_id` — приятная деталь, «где я это надиктовал». Уже добываемо
      через `NSWorkspace` (в `text_paster.rs` фокус целевого приложения уже трекается).

### 4.3 Окно меню-бара

Сейчас: `tray::TrayIconBuilder` с нативным `Menu` (`ui/tray.rs`, `ui/menu.rs`),
три пункта — Preferences / Paste Last Recording / Quit.

Станет: отдельное окно-панель, привязанное к иконке в статус-баре.

Технически:
- Отдельный Tauri-window: `decorations: false`, `transparent: true`,
  `alwaysOnTop`, `skipTaskbar`, ленивая инициализация.
- Позиционирование по rect иконки трея — Tauri v2 отдаёт координаты
  в `TrayIconEvent::Click`. Дальше `set_position` относительно них.
- **Non-activating panel**: окно не должно забирать фокус у приложения,
  в которое пользователь диктует. В проекте уже есть решение этой задачи для
  попапа — `ui/window.rs:show_window_without_focus()` (две реализации под
  `cfg`). Переиспользовать.
- Закрытие по клику вне окна: `on_focus_changed` → hide.
- Стекло: `window-vibrancy` + `NSVisualEffectMaterial::Popover` или `HudWindow`.

Содержимое (набросок):
- Переключатель активного пресета (радио-список).
- Последние N записей из истории с копированием в один клик.
- Кнопки: полная история, настройки, пауза/включение хоткеев, выход.
- Статус: активный провайдер, состояние микрофона.

Решить:
- [ ] Панель заменяет главное окно настроек целиком, или настройки остаются
      отдельным окном?
- [ ] Оставить ли левый клик = панель, правый клик = старое нативное меню
      (быстрый выход, если панель зависнет)?
- [ ] Размер: фиксированный или растёт под контент?

### 4.4 Стекло

- `window-vibrancy` в `Cargo.toml`, применяется при создании окон.
- В CSS фон окна прозрачный; Tailwind-тема переводится на полупрозрачные

### Этап 1 — уборка ✅

  то есть дев-сессии тоже уходили наружу. Для личного проекта телеметрия не нужна.

  `vitalii-zinchenko/dictara` с их minisign-ключом — любой их релиз мог

  `tauri-plugin-updater`.
- Удалены `landing/`, `.github/`, `security/`, `SETUP_TRANSCRIPTION.md`.

### Этап 2 — переименование в VoiceFlow ✅
- Продукт, crate (`voiceflow`, `voiceflow-keyboard`), bundle id
  (`app.voiceflow` / `app.voiceflow.dev`), Info.plist, README.
- **Миграция Keychain** (`keychain::migrate_legacy_bundle`): ключи копируются
  из старого bundle id в новый при первом запуске. Старые записи не удаляются —
  если что-то пойдёт не так, они всё ещё в Keychain Access.
- `LICENSE` сохраняет копирайт апстрима (этого требует MIT), к нему дописана
  заметка о форке.

### Этап 3 — пресеты ✅
- `src-tauri/src/presets.rs`: `Preset { id, name, provider, model, baseUrl,
  language, prompt, audioFormat }` + `PresetsConfig { presets, activeId }`.
- В Keychain теперь только `ProviderCredentials { apiKey }` — один секрет на
  провайдера. Модель, эндпоинт и язык переехали в пресет, поэтому переключение
  больше не трогает Keychain.
- Миграция со старой схемы: каждый настроенный провайдер становится пресетом,
  бывший `activeProvider` становится активным.
- Команды: load/save/duplicate/delete/setActive/**cycleActive**/reorder/test +
  `listProviders`.
- Клиенты получили `TranscriptionOptions` — язык и промпт теперь передаются
  провайдеру (раньше не передавались вообще).

### Этап 4 — история ✅
- SQLite через `rusqlite` (bundled) + FTS5 для поиска. **Аудио не хранится.**
- Пишется после каждой удачной транскрипции: текст, длительность, пресет,
  провайдер, модель и **приложение, куда вставили** (`NSWorkspace`,
  снимается до вставки, пока фокус ещё у цели).
- Ретеншен настраивается (30/90/365 дней или «навсегда»), чистка на старте.
- Ошибка записи в историю не роняет вставку — это побочная запись.

### Этап 5 — панель меню-бара ✅
- Нативное меню заменено окном `menubar`: переключатель пресетов, последние
  записи с копированием и повторной вставкой, настройки, выход.
- Стекло — `window-vibrancy` + `NSVisualEffectMaterial::Popover`.
- Позиционируется по rect иконки трея, закрывается при потере фокуса.
- Правый клик по иконке оставляет старое нативное меню как страховку.

### Этап 6 — лаборатория попапа ✅
- Орб рисуется WebGL2-шейдером (`src/components/orb/`).
- **Oil** — диск с 2–4 пигментными пятнами. Каждое пятно вращается по своей
  орбите со своей скоростью, цвет пикселя — взвешенное по расстоянию
  смешение пятен. Шум используется только для варпа координат, на низкой
  частоте.

  > Первая версия красила диск шумовым полем с 5–6 октавами fbm. На реальных
  > размерах (96–140 px) это давало мелкое зерно, которое читалось как
  > пиксельная сетка. Дискретные пятна — то, чем «две-три краски, размешанные
  > вместе» и являются на самом деле.

- **Smoke** — ridged-шум (`1 - |noise|`), дающий яркие тонкие нити вместо
  ровной серой мути, плюс восходящая адвекция и вращение.
- Варианты: Vapor Trail (белый/синий/фиолетовый, дефолт), Duotone, Marble,
  Lava, Aurora, Mercury / Filament, Ember, Ink, Plume, Toxic.
- Кастомизация: количество пигментов (2–4), скорость, турбулентность,
  мягкость края, свечение, реактивность, размер, палитра.
- Выбор сохраняется в конфиг и применяется к реальному попапу; размер окна
  попапа считается из размера орба.

### Этап 9 — матовый орб, Escape, непрозрачная панель ✅

- **Орб стал матовым.** Убраны sheen, rim light и затемнение к краю — всё, что
  имитировало глянцевую сферу. Слайдер `glow` переименован в `saturation`
  (в Rust — `#[serde(alias = "glow")]`, старые конфиги читаются), теперь он
  усиливает пигмент, а не блик.
- **Круг больше не разваливается.** Пятна смешивались гауссовыми весами, а
  гауссиана падает в ноль: там, где все пятна далеко, веса обнулялись,
  нормировка давала чёрный, и диск рвался — особенно в processing, где пятна
  сжимались. Заменено на обратно-дистанционные веса (интерполяция Шепарда,
  `1/dᵏ`), которые не обнуляются никогда. Маска диска не зависит ни от
  состояния, ни от уровня, ни от варпа — силуэт неизменен по построению.
  Единственное место, где форма ломается, — распыление, и только на выходе.
- **Escape полностью отменяет запись.** Обрабатывается в `keyboard_listener.rs`
  до матчинга шорткатов, шлётся `RecordingCommand::Cancel` (аудио
  выбрасывается, транскрипции нет), клавиша проглатывается. Крестик из попапа
  убран — попап специально не берёт фокус, поэтому кнопка там была
  единственным способом отменить; глобальный Escape эту роль закрывает.
- **Панель меню-бара стала непрозрачной.** Vibrancy убран целиком вместе с
  зависимостью `window-vibrancy`. Полупрозрачная панель ставит фон рабочего
  стола в конкуренцию с текстом на каждой строке, и подкрученным контрастом это
  не лечится. Теперь обычные токены темы, никаких теней текста и
  пооконных переопределений. Окно остаётся transparent только ради скруглённых
  углов, фон рисует страница.

### Этап 8 — состояния орба ✅

Одно и то же тело, четыре режима движения:

| Состояние | Движение |
|-----------|----------|
| `idle` | Пятна жмутся к центру, медленный поворот |
| `recording` | Орбита раскрывается, скорость растёт от голоса |
| `processing` | Быстрое плотное вращение (ramp-in, без рывка) |
| `dispersing` | Пятна разлетаются, диск размывается шумом |

Бэкенд держит окно попапа открытым лишние 600 мс после вставки текста
(`DISPERSE_DURATION` в `recording/controller.rs`), иначе анимация распыления
обрывалась бы на первом кадре. Событие `Stopped` теперь эмитится **до**
скрытия окна, а не после.

### Этап 7 — редизайн ✅
- Акцент сменён с серого на фиолетовый, нейтрали потеплели, радиус увеличен.
- Новая навигация настроек: Presets · History · Popup · Shortcuts · System.
- Попап переписан: орб вместо серой плашки, контролы появляются по наведению.

## 7. Что сохранить при любом рефакторинге

Работающие и небанальные вещи — их логику переносим, а не изобретаем заново:

- Обработка Fn/Globe (`crates/keyboard/src/macos.rs`, `globe_key.rs`), включая
  конфликт с эмодзи-пикером macOS.
- Стейт-машина записи (`recording/state_manager.rs`) и edge-cases —
  см. `notes/edge-cases-to-improve.md`.
- Вставка текста (`text_paster.rs`): clipboard + CGEvent, восстановление буфера,
  фокус целевого приложения.
- Показ окна без отбора фокуса (`ui/window.rs:show_window_without_focus`) —
  прямо понадобится для панели меню-бара.
- Проблема фокуса попапа — `notes/recording-popup-focus-issue.md`.
- Отличия провайдеров в API: multipart, MP3-конверсия, таймаут 120с
  (см. коммиты `29ac9ca`, `4bf11ad`).
- Silero VAD-пайплайн (`recording/vad.rs`) — 512 сэмплов/фрейм, контекст 64.

## 8. Риски

| Риск | Влияние | Митигация |
|------|---------|-----------|
| Миграция конфигов теряет ключи из Keychain | Среднее | Секреты в Keychain не трогать вообще, мигрировать только Store |
| Vibrancy убивает читаемость текста | Среднее | Проверить обе темы на раннем прототипе панели |
| Панель меню-бара крадёт фокус у целевого приложения | Высокое | Переиспользовать существующий non-activating код |
| История разрастается и жрёт диск | Среднее | Ретеншен с самого начала, а не «потом» |
| Рефакторинг под пресеты ломает рабочее приложение | Среднее | Этап 2 делать в ветке, старый UI поверх новой модели до перехода на новый |
